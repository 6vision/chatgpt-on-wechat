委任は、ある Agent が別の Agent に助けを求める仕組みです。[Sub Agent](/ja/multi-agent/subagent) と違い、対象はその場で作られる存在ではありません。自分のワークスペース、記憶、スキル、セッション、スケジューラを持つ常駐の同僚です。自分の環境で回答し、その結果は依頼した Agent に戻ります。ユーザーに直接送られることはありません。

<Note>
  `agent_delegate` ツールは、チームの会話——有効な Agent が 2 つ以上あり、会話に同僚がいる場合——にのみ現れます。単一 Agent の構成では表示されません。
</Note>

## Sub Agent か同僚か

| | Sub Agent | 委任 |
| --- | --- | --- |
| 寿命 | 1 つのタスクのために作られ、終われば消える | 常駐 Agent、事前に設定 |
| ワークスペース | 呼び出し元と共有 | 独立 |
| 記憶 | 自前のものは持たない | 独立 |
| アイデンティティ | 匿名 | Agent 一覧に現れ、チャネルを持てる |
| 結果 | その場で返る | その場で返る |

自分の作業を並列化するなら Sub Agent。そのタスクが本来別の担当のもの——そのコードベース、そのナレッジベース、その顧客を持つ Agent のもの——であれば委任します。

## 委任は同期的

委任はタスクを渡し、同僚の回答を待ってからそれを返します。呼び出しは同僚が完了するまで（または時間予算が尽きるまで）ブロックするため、ポーリングする状態も、追跡するハンドルもありません。

```
agent_delegate(agent_id="research", task="...")
  -> { status: "done", content: "..." }
```

内部では、この実行は依然として対象のワークスペースに記録され、その親は依頼元の run です。したがって委任の連鎖はどちらの端からもたどれます。

## 委任できる相手

委任できる相手は、現在の会話にいる同僚——コンテキストの「チームの会話」セクションに並ぶ名簿そのもの、ID も含めてです。委任はユーザーが構成したチームの内側に留まり、許可リストが認めていても、会話の外にいる Agent へ渡すことはありません。同僚でない相手を指定するとツールは拒否し、実際に委任できる同僚を挙げます。

## パラメータ

`agent_id` —— 同僚の ID（「チームの会話」セクションでその人に表示される `@id`）。`task` —— この会話を見なくても同僚が動ける、自己完結したタスク説明。

## ガード

委任は完全な Agent 同士で行われるため、境界が設けられています。

- **メンバー** —— 対象はこの会話の同僚でなければならない
- **許可リスト** —— 誰が誰に頼めるか。未設定ならすべての Agent 間で可能
- **循環** —— すでに連鎖に含まれる Agent へは再委任できない
- **深さ** —— 1 つの連鎖で許される委任の段数
- **サイズ** —— 1 回のタスク本文の上限
- **時間予算** —— 1 回の委任 run が許される最長時間。超えれば打ち切られる

## 設定

```json
{
  "agent_delegation": {
    "enabled": true,
    "allowed_targets": {
      "assistant": ["research", "support"],
      "research": []
    },
    "max_depth": 3,
    "timeout_seconds": 600,
    "max_message_chars": 8000
  }
}
```

| フィールド | 既定値 | 意味 |
| --- | --- | --- |
| `enabled` | `true` | `false`、またはブロック全体を `false` にするとツールを提供しない |
| `allowed_targets` | 未設定 | 送信元 Agent ID から到達可能な ID への対応。`"*"` は任意。未設定ならすべての組み合わせを許可。対象はさらに現在の会話の同僚に限定される |
| `max_depth` | `3` | 1 つの連鎖での委任段数（1-8） |
| `timeout_seconds` | `600` | 1 回の委任 run の時間予算（0.01-3600）。ローカル実行は期限が来るとキャンセルされる |
| `max_message_chars` | `8000` | 1 回の委任タスクの長さ上限 |

上記の `"research"` のように空配列を指定した Agent は、委任を受けることはできますが、さらに外へ委任することはできません。
