## Recommended: One-line upgrade

Use `cow update` to pull the latest code and restart the service in one step:

```bash
cow update
```

The command runs the following automatically:

1. Pull the latest code (`git pull`)
2. Stop the running service
3. Update Python dependencies
4. Reinstall the CLI
5. Start the service

<Note>
  If the Cow CLI is not installed, `./run.sh update` performs the same operations.
</Note>


## Web console one-click update

Source installs can also upgrade from the Web console without opening a terminal.

1. Click the version string in the left sidebar footer to open the pop-up menu. Opening it does **not** contact GitHub.
2. Click **Check for update** to fetch version info — the only network request. If a newer version exists, the same row turns into **Update now** with a small red dot.
3. Click **Update now**. The console reuses the same path as `cow update` (`git pull`, dependency install, CLI reinstall) and then restarts the service. The **Release notes** entry opens the GitHub releases page for the full changelog.

The update only touches the git checkout. User data lives outside the repo (`agent_workspace`, default `~/cow`) and `config.json` is git-ignored, so `git pull` never overwrites them — no backup is taken. The updater records the current git commit; if the new code fails to import, it resets the checkout to that commit and leaves the running process untouched.

After a successful update the console reconnects on its own and shows the new version.

<Note>
  Docker images and the packaged desktop app cannot use this button. Docker stays on `docker compose pull`; the desktop client keeps its built-in updater. On Windows, run `cow update` in a terminal — the Web console cannot restart that process from inside itself.
</Note>

### Rollback

If a successful update misbehaves, reset to the previous commit:

```bash
cow stop
git reset --hard <previous-commit>   # recorded in tmp/web-update-status.json
cow start
```

## Manual upgrade

Run the following inside the project root:

```bash
git pull
pip3 install -r requirements.txt
pip3 install -e .
```

Then restart the service:

```bash
# Using Cow CLI (recommended)
cow restart

# Or using run.sh
./run.sh restart

# Or restart manually with nohup
kill $(ps -ef | grep app.py | grep -v grep | awk '{print $2}')
nohup python3 app.py & tail -f nohup.out
```

## Docker upgrade

<Tip>
  Back up `config.json` before upgrading.
</Tip>

Run every step in the directory that contains `docker-compose.yml`. Compose mounts `./cow-data` from that directory. Copy the files out before `pull` and `up -d`. A recreated container cannot yield them. `docker cp` works on a stopped container too, so copy while the old container still exists. Do not run `docker compose down` or `docker rm` until the copy finishes. Skip the copy when `COW_DATA_DIR` is already set: `/app/config.json` is then the image template (`docker/Dockerfile.latest` runs `cp config-template.json config.json`) and would overwrite `./cow-data/config.json`. Without `COW_DATA_DIR`, the saved config is the writable-layer `/app/config.json`, and the WeChat login is `/home/agent/.weixin_cow_credentials.json`.

### 1. Copy the files out

Replace `chatgpt-on-wechat` if that is not the container name. If the container is already gone, the files are gone. When this prints `COW_DATA_DIR=` and a path, skip the copies. An empty value prints nothing. Run the copies only when it prints nothing. Skip the WeChat line if you never logged in.

```bash
sudo docker inspect --format '{{range .Config.Env}}{{println .}}{{end}}' chatgpt-on-wechat | grep -E '^COW_DATA_DIR=.+'
```

```bash
mkdir -p ./cow-data
sudo docker cp chatgpt-on-wechat:/app/config.json ./cow-data/config.json
sudo docker cp chatgpt-on-wechat:/home/agent/.weixin_cow_credentials.json ./cow-data/weixin_credentials.json
```

### 2. Add `COW_DATA_DIR` and the `./cow-data` volume

Add both to the compose file, or to the NAS volume and environment settings, before `up -d`. `docker compose pull` does not edit a saved compose file. On every start, a set compose environment value overrides the same setting loaded from `config.json`. `CHANNEL_TYPE: 'web, weixin'` and a blank string such as `DEEPSEEK_API_KEY: ''` replace the file's value. Remove or edit those variables to keep what you saved.

```yaml
    environment:
      COW_DATA_DIR: '/home/agent/.cow'
    volumes:
      - ./cow:/home/agent/cow
      - ./cow-data:/home/agent/.cow
```

### 3. Pull, chown to `agent`, then start

`sudo docker cp` keeps mode `0600` and sets the owner to root. `docker/entrypoint.sh` chowns only the mount directory, then runs as `agent`, which cannot read that WeChat file. `docker/Dockerfile.latest` creates `agent` with `useradd -r` and does not pin a uid. Read the uid and gid, put the two numbers in `UID:GID`, and delete a path you did not copy. Replace the image name if yours differs. Chown before `up -d`.

```bash
sudo docker compose pull
sudo docker run --rm --entrypoint id zhayujie/chatgpt-on-wechat -u agent
sudo docker run --rm --entrypoint id zhayujie/chatgpt-on-wechat -g agent
```

```bash
sudo chown UID:GID ./cow-data/config.json ./cow-data/weixin_credentials.json
```

```bash
sudo docker compose up -d
```

## Desktop client upgrade

The [desktop client](/guide/desktop) has built-in auto-update: it checks for new versions automatically and prompts you, so you can download and restart to upgrade in one click.

You can also grab the latest version anytime from the [download page](https://cowagent.ai/download/).
